# Mario Kart graphics upgrade — October 13, 2026

The Retro Games Mario Kart runtime renders every client at 1920×1080, 16:9.
Its existing interpolated 60 FPS presentation is retained. The simulation,
controller transport, countdown and audio remain at their original cadence.

## Changes

- Widen the world projection and preserve geometry proportions. Orthographic
  detection checks the entire projection W column because the game multiplies
  its camera into the projection stack; testing only its final element can
  misclassify track polygons and create gaps.
- Anchor race HUD widgets within each player's widescreen viewport. Keep top
  LAP/TIME labels and digits together; keep central widgets centered.
- Render to a 1080p scene framebuffer and apply FXAA in a final pass. Restore
  native renderer state after postprocessing and course-TV downsampling.
- Import the pinned MK64 Reloaded v2026.04.03 pack. Native decoded RGBA checksums
  identify HD replacements without modifying emulated game memory. Palette
  variants, overlapping kart halves, atlas tiles and partial strips are mapped.
  The pack maps 10,429 PNGs; 138 unsupported/unidentified PNGs retain original
  textures. Generated files retain the pack's credits.
- Stream WebP assets with six concurrent downloads and a 64 MiB bitmap cache.
  Protect recycled GPU texture slots from late asynchronous uploads. Cancel
  active and queued downloads on stop and delete native GPU resources.
- Downsample course televisions on the GPU to their original 320×240 buffer;
  widescreen TV capture crops centrally to preserve the original 4:3 content.

## Verification

Physical-GPU Chromium testing used an NVIDIA RTX 3080. The original-resolution
baseline measured 29.94 simulation/render frames per second. The upgraded build
measured 29.98 simulation frames and 59.97 presentations per second, with game
clock speed 0.9994 times wall time. All 1,150 compared simulation hashes matched.
There were no JavaScript/WebGL errors or failed HD downloads. At capture, 5,557
HD uploads had applied, including karts, course textures and HUD assets; decoded
bitmap usage stayed within 64 MiB and returned to zero on shutdown.

A same-frame FXAA-on/off comparison changed 102,149 pixels above a two-channel
value threshold. The final screenshot was visually checked for track continuity,
texture replacement and HUD placement. Unit checks cover actual texture hashing,
HUD anchors, projection classification, palette decoding, GPU binding restoration,
slot recycling and cancelling queued bootstrap downloads.

Software WebGL was too slow for the earlier dual-1080p timing run. Hardware
results do not guarantee 60 FPS on every device. HD assets may initially show
original texels while streaming; uncovered resources retain original textures.
The browser integration fixture uses disposable accounts/databases and the real
Retro Games Socket.IO flow, without opening production databases.

Two- and four-player physical-GPU integration checks passed. Four-player
rendering measured 59.55–59.95 FPS with injected network delay/jitter and 200
matching frame hashes. Both flows checked controls, audio, two cooperative
restarts and departure; two-player testing also passed retained reconnect.
Every client used a 1920×1080 canvas with active FXAA and HD replacements.
The matching native pair was atomically published to `instance/mk64/build`;
the previous pair remains under `.tmp/mk64-hd-20261013/live-build-before`.
No application-service restart is needed; players must reload the game.
