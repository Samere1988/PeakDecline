# Mario Kart runtime and netplay verification — October 13, 2026

Scope: Mario Kart launched from `/games/retro`. The retired standalone page,
relay and associated browser tests were removed after being archived under
`.tmp/mk64-netplay-20261013/`. The shared controller, touch and account save
integrations remain in use.

## Changes

- Default 60 FPS presentation interpolates stable camera, kart and shadow
  transforms. Original 30 Hz simulation/input/audio timing remains intact.
  Particle, HUD and menu animation cadence is unchanged.
- Native stop is cooperative and awaited before restart. Runtime failures reach
  the session; a module announces loaded only after native initialization.
  Cancellation prevents stale startup/abort callbacks from affecting a new game.
- MK64 input lead uses lobby RTT and a recent jitter window, increasing promptly
  and decreasing after stable measurements.
- A retained tab can reconnect within 15 seconds, replay complete input rows and
  resubmit exact pending inputs. Disconnected racers pause the group. Spectators
  use bounded history and accelerated catch-up without pausing racers.
- Failed or timed-out loading spectators are removed independently. Intentional
  departure waits for the server acknowledgement before navigating away.
- Build hashes are cached across the full asset catalog and cold file hashing
  runs outside the gevent relay loop. Connection state is rechecked after this
  asynchronous validation to avoid orphaned rooms.
- State checksums cover additional menu/course/race state and all eight karts.
  This improves diagnostics; it is not a full save-state or rollback system.

## Verification

The Python checks use isolated databases. The real application factory also
passed page preflight with temporary databases. The shared server suite passed
109 tests, including recovery, expiry, spectator isolation, build invalidation
and disconnect-during-create. The native input core and focused MK64 session
tests passed, including pending-input replay, bounded queues, delayed departure,
startup errors and cancellation during restart.

The browser fixtures use the real native WASM, adapters and `/retro` Socket.IO
relay. Reports are under `.tmp/mk64-netplay-20261013/`:

- Two players: driving, audio and 200 consecutive hashes passed; roughly
  29.0 simulation FPS / 58.0 presentation FPS. Retained reconnect and two
  restarts passed, with references to the old modules proving they stopped.
- Four players with 40 ms one-way delay and periodic 80 ms jitter: 200 hashes,
  driving, audio, two restarts and explicit departure passed. Four separate
  software-rendering processes measured roughly 27.1 simulation FPS /
  54.2 presentation FPS.
  The initial departure check exposed the dropped leave-message bug described
  above; the final run verifies acknowledgement before navigation and waits
  for cooperative native shutdown before checking that frames remain frozen.
- Spectator: a 1.6-second stall accumulated 51 rows while the racer advanced 48
  frames. Catch-up restored matching hashes. Retained spectator reconnect,
  spectator departure and a blocked ROM download left the racer running.

The four-player control sharing one software GPU process managed only roughly
11 simulation FPS / 23 presentation FPS. The separate-process measurement avoids
serializing sixteen split-screen views through that single software renderer.
Neither measurement guarantees 60 FPS on every player's hardware or network.

`tests/games/mk64_presentation_browser.cjs` compares native 30/60 presentation
with the same deterministic inputs and linker map. The endurance run passed
6,100 hash comparisons through a completed three-lap race. Both modes recorded
eight inventory clears after item acquisition. The 60 FPS mode measured 60.08
presentations and 29.96 simulation frames per second, with 0.999 game seconds
per wall-clock second. Normal stop, failed-network stop and stop while blocked
on input all passed, without browser errors. The report is
`.tmp/mk64/presentation-regression-endurance.json`.

## Further graphics work

[SpaghettiKart](https://github.com/HarbourMasters/SpaghettiKart) provides modern
resolution/widescreen settings, interpolated frame rates and antialiasing.
[MK64 Reloaded](https://github.com/GhostlyDark/MK64-Reloaded) supplies HD texture
replacements for supported ports including SpaghettiKart. Those assets do not
load directly into this MKart360 browser runtime. Supporting them requires a
compatible asset loader and renderer, or a browser migration to SpaghettiKart.
This change retains the existing 640×480, 4:3 renderer.
